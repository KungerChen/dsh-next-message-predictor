# 第 3 批质量优化记录（O05 / O02 / O03 / O04）

对应 PLAN 第 3 批：**O05 真实会话回放基线 → O02 提示词 v3 → O03 语义过滤 → O04 固定快模型 + 关闭推理**。
验收口径：v3 的匹配率、弃权正确率不低于 v2，违规数为 0；单测全过；P1/P2 复跑。

## 1. O05 真实会话回放（`eval/replay-eval.mjs`）

- 样本定义：从本机 `~/.dsh/sessions` 的真实会话里提取“已完成回合的上下文 + 用户真实发出的下一条消息”，作为标准答案。上下文使用生产同款 B02 裁剪与脱敏；报告只写分数与哈希，不写对话正文。
- 过滤：跳过子代理（`delegationDepth>0`）与临时目录会话；用户消息 ≤1000 字；期望下一条 2–300 字；每个会话最多 8 条。
- 通过 scratch profile 的评测 Host（`/api/nmp-eval/rpc`）调用真实 `deepseek-official/deepseek-flash`；单次运行 42 条（来自 15 个人工会话，平均上下文约 830–1010 估算 token）。
- 指标：触发率、完全匹配率、前缀字符/覆盖率、编辑距离比率、潜在节省输入、O03 语义命中数、延迟、token。

## 2. 基线 vs v3（同一组 42 条样本，交集 42/42）

| 指标 | v2 基线 | v3（O02+O03+O04） |
|---|---:|---:|
| 给出建议比例 | 100% | **78.6%**（21.4% 弃权） |
| 完全匹配率（建议 = 用户真实下一条） | 2.4% | **9.1%** |
| 平均前缀字符数 | 0.43 | **1.27** |
| 前缀覆盖率/潜在节省输入 | 4.3% | **13.6%** |
| 平均编辑距离比率 | 0.248 | **0.291** |
| O03 语义违规数 | 0 | **0** |
| 延迟 P50 / P95 | 1411 / 1984 ms | 1476 / 2070 ms |
| 平均输入 / 输出 token | 200 / 17 | 360 / 11 |

**结论**：v3 的匹配率（完全匹配 2.4%→9.1%、前缀覆盖 4.3%→13.6%）与编辑距离均优于 v2，违规为 0；同时触发率从 100% 降到 78.6%，符合“宁可沉默”的目标。延迟略升 4–5%，输出 token 更少（maxTokens 96）；输入 token 较高主要来自 v3 更长的检验规则与首次运行缓存差异，单次预测成本仍然很低。

报告：`eval/replay-v2-baseline.json`、`eval/replay-v3.json`（均含逐条哈希分数，不含正文）。

## 3. O02 提示词 v3（`src/shared/prompt.js`）

- `PROMPT_VERSION` 递增为 `nmp-p2-v3`；新增核心检验：“用户看到这句话，会不会觉得‘这正是我正要打的’？不会就返回 null”。
- 长度：中文 2–30 字为主、最多 40 字；英文 2–12 词；单行。
- 优先级：用户已说过下一步 → 写那句；助手问是否继续且用户此前一直同意 → 简短确认；刚改文件未验证 → 让助手跑测试/检查；其余弃权。
- 禁止：感谢/评价（不错/谢谢）、助手口吻（我来/让我）、复述助手建议、解释/引用/多候选。
- 保留既有约束：不编造用户事实/授权、不扩大范围、选项不明只问细节、任务结束不制造新任务、私人信息/审批返回 null。
- 输出校验上限 `maxSuggestionGraphemes` 从 160 降到 60（容纳英文 12 词与中文 40 字）。

## 4. O03 语义过滤（`src/host/semantic-filter.js`）

- 严格 JSON/输出校验之后运行，只拒绝不修复：
  - 助手口吻开头（我来/让我/我可以/建议你/…）；
  - 感谢/评价（谢谢/感谢/辛苦了/不错/很好/好主意/厉害）；
  - 元话语（没有建议/暂无建议/无建议/…）；
  - 错误文本（api error/timed out/timeout/error:/出错/报错）；
  - 标签前缀（建议：/User:/Assistant:/Suggestion:/Reply:）；
  - 与助手最后一句字符 bigram 覆盖率 ≥ 0.8（复述）。
- 命中：`outputRejects` 计数，结果记录 reason 为 `semantic-<rule>`（写入 O01 的 events.jsonl），不展示建议。
- 固定测试模式不经过滤（离线回归保持确定性）。

## 5. O04 默认固定快模型、关闭推理

- 默认配置改为：`modelMode: 'fixed'`、`provider: 'deepseek-official'`、`model: 'deepseek-flash'`、`reasoningEffort: 'off'`、`maxOutputTokens: 96`。
- 固定路由不可用（provider/model 未配置/未知等）时，`produce()` 只回退一次到当前会话模型（source=`fallback-session`，记录 `route-fallback` 诊断）；显式配置错误（如不支持的 reasoning effort）不回退、直接报告。
- 设置页仍可改回“跟随会话模型”；桌面 patch 只有 `enabled: true`，重启后会使用新的默认固定路由。

## 7. 已知限制与后续

- 回放样本来自本机人工工作区会话（近 14 天，15 会话 42 条）。
- v2 基线与 v3 的输入 token 对比受提供方缓存命中影响，报告中的 usage 不是统一计费口径。
- 语义过滤规则是保守关键词/重合度判断，可能有漏检或误杀；命中会写入 O01，可后续用真实数据复盘。
- 固定路由回退只在 prepare 阶段失败时触发；流式失败仍按“模型失败不重试”处理。
- 第 4 批（O06 右方向键/手动入口、O07 冲突检测、O08 回合摘要）未开始。
- 桌面重启后新默认才生效。
