why_h: 왜 쓰는가
why_p: 어시스턴트와 함께 일하다 보면 답장의 상당수는 짧고 예상하기 쉽습니다. “계속해”, “테스트 돌려 봐”, “변경 내용 보여 줘”. 이 플러그인은 그런 후속 한마디를 미리 써서 입력창에 놓아 둡니다.
c1_h: 타이핑이 줄어든다
c1_p: 자주 쓰는 후속 메시지를 키 하나로 채웁니다. 채운 뒤에는 직접 입력한 글자와 똑같아서 고칠 수도, 되돌릴 수도 있습니다.
c2_h: 방해하지 않는다
c2_p: 입력을 시작하는 순간 제안은 물러납니다. IME 조합 중이거나 메뉴가 열려 있을 때는 나타나지 않습니다. 모델이 확신하지 못하면 아무것도 내놓지 않습니다.
c3_h: 선을 넘지 않는다
c3_p: 하는 일은 입력창에 글자를 넣는 것뿐입니다. 플러그인에는 “메시지 전송” 코드가 전혀 없으며, 보낼지 말지는 언제나 사용자가 정합니다.
c4_h: 비용을 통제할 수 있다
c4_p: 기본적으로 저비용 모델을 쓰고, 하루 요청 수와 토큰 수에 한도가 있습니다. 반복해서 쓰는 짧은 문장은 모델을 호출하지 않고 바로 제안합니다.
c5_h: 개인정보를 중시한다
c5_p: 전송 전에 키, 토큰, 이메일 주소, 전화번호로 보이는 내용을 가립니다. 브라우저는 초안을 업로드하지 않습니다. 로컬 통계는 숫자만 기록하고 글은 기록하지 않습니다.
c6_h: 사용량이 투명하다
c6_p: 최근 7일의 요청 수, 수락률, 응답 시간, 토큰 사용량이 설정 페이지에 있어 쓸 만한지 한눈에 알 수 있습니다.

send_h: 무엇을 전송하는가
send_p: 예측 한 번에 모델로 요청을 한 번 보내며, 자동 재시도는 없습니다. 내용은 현재 세션의 최근 **사용자 메시지와 어시스턴트의 최종 텍스트 답변**의 발췌이며, 기본적으로 최대 12개, 약 2,000 토큰입니다.
sb1: 도구 호출의 인자와 출력, 추론 과정, 시스템 프롬프트는 포함하지 않습니다.
sb2: 전송 전에 개인 키, API 키, 토큰, 비밀번호, 이메일 주소, 휴대전화 번호, 신분증 번호, 홈 폴더 경로의 사용자 이름으로 보이는 내용을 자리 표시자로 바꿉니다(규칙 기반이며, 모두 찾아낸다고 보장할 수는 없습니다).
sb3: 브라우저 페이지는 세션과 턴의 식별자만 보내며, 초안, 첨부 파일, 대화 내용은 보내지 않습니다. 모델에 보낼 내용은 백그라운드 쪽이 DSH 자체의 세션 기록에서 읽어 옵니다.
sb4: “{ui:settings.habits}”는 이 컴퓨터에서 사용자가 보낸 짧은 메시지를 비교할 뿐이며, 모델을 호출하지 않습니다.
send_more: 자세한 설명과 로컬 데이터를 삭제하는 방법은 [개인정보와 데이터 경계](docs/PRIVACY.md)에 있습니다.
faq_h: 자주 묻는 질문
q1: 나 대신 메시지를 보내 버리지는 않나요?
a1: 아닙니다. 제안을 수락하면 입력창 자체의 삽입 인터페이스로 글자를 채울 뿐입니다. 플러그인 코드에는 제출하거나 전송하는 호출이 없습니다.
q2: 비용은 얼마나 드나요?
a2: 예측 한 번은 아주 짧은 모델 호출입니다(기본 출력 한도 96 토큰). 기본 일일 한도는 200회, 50만 토큰이며, 한도에 이르면 그날은 더 호출하지 않습니다. 더 아끼고 싶다면 “{ui:preset.saver.name}” 모드를 고르세요. 직접 요청할 때만 예측합니다. 실제 사용량은 설정 페이지의 “{ui:settings.resultTitle}”에서 볼 수 있습니다.
q3: 왜 가끔 제안이 없나요?
a3: 의도된 동작입니다. 모델이 확신하지 못하면 내놓지 않고, 조건에 맞지 않는 출력(너무 길거나, 여러 줄이거나, 어시스턴트의 말투인 것)도 버립니다. 설정 페이지의 상태 줄에 지금 제안이 없는 이유가 표시됩니다. 제안이 필요할 때는 <kbd>Alt</kbd>+<kbd>\\</kbd>를 누르세요.
q4: 제안은 정확한가요?
a4: 짧고 분명한 후속 메시지에 강합니다. 계속 진행 확인, 검증 요청, 세부 사항 질문 같은 것들입니다. 사용자만 아는 일은 맞힐 수 없으며, 그럴 때는 조용히 있는 것이 올바른 동작입니다.
