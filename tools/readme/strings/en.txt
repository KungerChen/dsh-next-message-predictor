inst_p: Installation requires DeepSeek Harness `{fact:dsh_range}`. The GitHub package is ready to install without a build step.
inst_profile: Use the profile you open in DSH (`desktop` or `web` by default). Then **quit DSH completely and reopen it**.
s1: Open **Settings → {ui:settings.nav}**. Prediction is off on a fresh install.
s2: Choose a mode under “{ui:preset.title}”. In “{ui:settings.routeTitle}”, check that your DSH setup can use the proposed provider and model, or select “{ui:settings.routeModeSession}”. Save changes to the model fields.
s3: Turn on “{ui:settings.enabled}”. After the assistant replies, leave the input empty. To try it manually, click “{ui:ghost.predict}” or focus the empty input and press <kbd>Alt</kbd>+<kbd>\</kbd>.
route_note: Balanced and Saver default to `{fact:default_provider} / {fact:default_model}`. To use a different specific model, enter its DSH provider and model IDs. If DSH cannot resolve the configured model, a usable DSH default model may be used for that prediction.

fp_h: Model suggestions and your own phrases
fp_p: A prediction can offer model suggestions, followed by short messages you repeated in this conversation and your pinned phrases. Add or reorder pinned phrases in **Settings → {ui:settings.nav} → {ui:settings.sourcesTitle} → {ui:settings.pinned}** and save. “{ui:ghost.another}” cycles through available choices without an additional model call. After the existing choices run out, asking for another may call the model, subject to the limits.
fp_fallback: When the model has no usable result for a manual request, the plugin can offer your own phrases if available. Generating that fallback makes no additional model call.

send_p: A model prediction sends recent excerpts of **user messages and final assistant replies** from the active conversation branch to a model provider configured in DSH. The default input budget is {fact:default_context_messages} messages and about {fact:default_input_tokens} tokens, including the prediction instructions.
sb1: A short summary of the previous turn’s activity counts is included by default. Tool arguments, tool output, reasoning and system prompts are excluded.
sb2: Rule-based masking is enabled by default and replaces likely secrets and some personal identifiers. It can miss sensitive text.
sb3: Prediction and session-state requests from the browser carry identifiers and metadata. The backend reads sent messages from DSH. Drafts, attachments and references are excluded. Local statistics store counts, timings and identifiers without conversation or suggestion text.
sb4: Local candidates and the pinned-phrase list are not added to the model prompt. A phrase you already sent as a message can still appear as recent conversation context.
send_more: The full description, and how to delete the local data, is in [Privacy and data boundaries](docs/PRIVACY.md).
faq_h: FAQ
q1: Why did no suggestion appear?
a1: Check the current status in the settings. A paused conversation, an inactive window, a nonempty draft, a menu or active IME composition can block display. The model can also return no usable suggestion. Try manual prediction from the focused, empty input when the conversation is eligible.
q2: When are requests charged?
a2: Usage depends on the model provider and the tokens used in each dispatched request. Cycling through existing choices and building a local fallback add no model request. Use Saver mode to request predictions only when you need one.
