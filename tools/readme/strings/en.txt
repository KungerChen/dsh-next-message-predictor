why_h: Why use it
why_p: When you work with an assistant, many replies are short and easy to guess: “continue”, “run the tests”, “show me the changes”. This plugin writes that follow-up ahead of time and leaves it in the input box.
c1_h: Less typing
c1_p: Common follow-ups are one key away. Once filled in, the text behaves like anything you typed: edit it, undo it.
c2_h: No interruptions
c2_p: The moment you start typing, the suggestion steps aside. It stays away during IME composition and while a menu is open. When the model is not confident, it offers nothing.
c3_h: Never oversteps
c3_p: It only puts text into the input box. There is no “send message” code anywhere in the plugin; sending is always your decision.
c4_h: Cost under control
c4_p: A low-cost model by default, with daily limits on requests and tokens. Short phrases you keep repeating are offered directly, without calling the model.
c5_h: Privacy first
c5_p: Likely keys, tokens, e-mail addresses and phone numbers are masked before sending. The browser never uploads your draft. Local statistics store numbers, not text.
c6_h: Transparent usage
c6_p: Requests, acceptance rate, response time and token usage for the last 7 days are on the settings page, so you can see whether it is worth it.

inst_h: Installation
inst_p: Requires DeepSeek Harness `0.2.2-rc.1` (`>=0.2.2-rc.1 <0.3.0`). The plugin has no third-party dependencies and needs no build step. One command installs it:
inst_profile: The name after `--profile` is the profile you use every day: `desktop` for the desktop app, `web` for the web version. Afterwards **quit DSH completely and start it again**.
inst_d_sum: The <code>dsh</code> command is not found, or you want to install from a local folder
inst_d_p: The `dsh` command line lives in the DeepSeek Harness installation folder and can be called by its full path. To change the code yourself, clone the repository and install from the local folder:
ph_dsh: DSH install folder
ph_plugin: plugin folder
inst_d_tail: `<DSH install folder>` is where DeepSeek Harness is installed; `<plugin folder>` is the folder you just cloned.
steps_p: Then three steps to get going:
s1: Open **Settings → {ui:settings.nav}** and switch on “{ui:settings.enabled}”. It is off by default: until you enable it, no suggestion is shown and no model is called.
s2: Pick one under “{ui:preset.title}”. The default is “{ui:preset.balanced.name}”.
s3: For quicker access, click “{ui:settings.sidebarAdd}” in the top right corner.
upd_sum: Updating and uninstalling
upd_p: **Update**: if you installed from GitHub, uninstall and run the install command again; if you installed from a local folder, run `git pull` there. Then restart DSH. Refreshing the page is not enough: the page would be new while the background half is still old, and the settings page would report a version mismatch.
unin: **Uninstall**:
conflict: Enable only one composer-prediction plugin per profile. When another one is detected, this plugin pauses itself and says why on the settings page.
send_h: What it sends
send_p: Each prediction is a single request to the model, with no automatic retry. It contains excerpts of the most recent **user messages and the assistant’s final text answers** in the current session: at most 12 messages and about 2,000 tokens by default.
sb1: No tool-call arguments or output, no reasoning, no system prompt.
sb2: Before sending, likely private keys, API keys, tokens, passwords, e-mail addresses, mobile and identity numbers, and the user name in home-folder paths are replaced with placeholders (rule-based; it cannot promise to catch everything).
sb3: The browser page sends only session and turn identifiers, never the draft, attachments or any conversation text; the content for the model is read by the background half from DSH’s own session records.
sb4: “{ui:settings.habits}” only compares the short messages you sent on this computer; no model is called.
send_more: The full description, and how to delete the local data, is in [Privacy and data boundaries](docs/PRIVACY.md).
faq_h: FAQ
q1: Will it send a message for me?
a1: No. Accepting a suggestion only puts text into the input box, through the input box’s own insertion interface; the plugin contains no call that submits or sends.
q2: How much does it cost?
a2: Each prediction is one very short model call (at most 96 output tokens by default). The default daily limits are 200 requests and 500,000 tokens; once reached, no more calls are made that day. To spend less, choose the “{ui:preset.saver.name}” mode, which predicts only when you ask. Actual usage is shown under “{ui:settings.resultTitle}” on the settings page.
q3: Why is there sometimes no suggestion?
a3: By design: when the model is not confident it offers nothing, and output that breaks the rules (too long, several lines, written in the assistant’s voice) is discarded. The state line on the settings page says why there is none right now. When you want one, press <kbd>Alt</kbd>+<kbd>\\</kbd>.
q4: Are the suggestions accurate?
a4: It is good at short, clear follow-ups: confirming, asking for verification, asking for details. It cannot guess what only you know, and in that case it should stay silent.

lim_h: Known limitations
l1: Verified on DSH `0.2.2-rc.1` only.
l2: Saving a setting makes the host restart the background half of the plugin; a prediction in progress is cancelled.
l3: Several windows share prediction results; hiding a suggestion in one window is not synchronised to the others in real time.
l4: The command palette and the feedback dialog are recognised by focus and modal traits; a wrong guess only means one suggestion less, never a stolen key press.
