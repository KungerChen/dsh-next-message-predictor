fp_h: モデルの候補と自分のフレーズ
fp_p: モデルの候補の後に、同じ会話で繰り返し送った短文と固定フレーズが続きます。**設定 → {ui:settings.nav} → {ui:settings.sourcesTitle} → {ui:settings.pinned}** で追加や並べ替えをして保存してください。「{ui:ghost.another}」で表示済みの候補を切り替えるだけなら、モデルへの追加リクエストはありません。用意された候補を使い切った後は、上限の範囲内でモデルに再度リクエストすることがあります。
fp_fallback: 手動予測でモデルから使える結果が得られないとき、登録済みなどのフレーズがあれば候補になります。この補完処理で追加のモデル呼び出しはありません。

shots: スクリーンショットは分離した Web 画面で、合成した会話とローカルの模擬モデルを使って撮影しました。設定は一例です。使用量と応答時間はデモ用の数値です。
send_p: モデルで予測すると、現在の会話分岐から最近の**ユーザーメッセージとアシスタントの最終応答**の抜粋を、DSH に設定したプロバイダーへ送ります。入力上限の既定値は {fact:default_context_messages} メッセージ、予測指示を含めて約 {fact:default_input_tokens} トークンです。
sb1: 既定で前のターンの操作回数を短くまとめて添えます。ツールの引数・出力、推論、システムプロンプトは含めません。
sb2: ルールに基づくマスキングは既定で有効です。秘密情報らしい文字列や一部の個人識別情報を置き換えます。検出を漏れる場合があります。
sb3: ブラウザーの予測・会話状態リクエストは識別子とメタデータを送ります。バックエンドは DSH の送信済みメッセージを読み、下書き・添付・引用は対象外です。ローカル統計は件数、時間、識別子を記録し、会話や候補の本文を保存しません。
sb4: ローカル候補と固定フレーズの一覧はモデルへの指示に追加されません。メッセージとして送ったフレーズは会話の抜粋に含まれることがあります。
send_more: 詳しい説明とローカルのデータを削除する方法は、[プライバシーとデータの境界](docs/PRIVACY.md) にあります。
faq_h: よくある質問
q1: 候補が出ないのはなぜですか？
a1: 設定画面の状態表示を確認してください。一時停止、ウィンドウが前面にない、下書きがある、メニューを開いている、IME 変換中といった条件では表示できません。モデルから使える候補が返らないこともあります。条件を満たすときは空の入力欄にフォーカスして手動予測を試せます。
q2: いつ料金がかかりますか？
a2: 料金は実際に呼び出したプロバイダーとトークン使用量で決まります。既存候補の切り替えとローカル候補の生成では追加リクエストはありません。必要なときだけ予測するには節約モードを使えます。
